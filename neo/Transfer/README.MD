# BasicTransfer

**Namespace:** `Neo\Transfer`

Базовый абстрактный класс для создания DTO (Data Transfer Object) с автоматическим заполнением свойств и встроенной валидацией данных.

`BasicTransfer` принимает массив данных, автоматически сопоставляет его с публичными свойствами наследника, преобразует вложенные массивы в DTO и запускает соответствующие методы валидации.

Весь процесс выполняется непосредственно при создании объекта.

## 1. Быстрый старт

Предположим, нам необходимо создать DTO для конфигурации компилятора шаблонов.

Создадим класс:

```php
<?php

namespace Neo\View\DTO;

use Neo\Transfer\BasicTransfer;
use Neo\Validator\Rule;

class CompilerTransfer extends BasicTransfer
{
    public string $basicPath;

    public array $brackets = ['{{', '}}'];

    public bool $isCached = true;

    public function validateBrackets(Rule $rule): Rule
    {
        return $rule
            ->required()
            ->array()
            ->size(2);
    }

    public function validateBasicPath(Rule $rule): Rule
    {
        return $rule
            ->required()
            ->string()
            ->min(1);
    }
}
```

Теперь передадим конфигурацию:

```php
$config = new CompilerTransfer([
    'basic_path' => 'resources/views',
    'brackets' => ['{{', '}}'],
    'is_cached' => false,
]);
```

Готово. Объект уже заполнен и прошёл валидацию.

```php
$config->basicPath; // resources/views

$config->brackets; // ['{{', '}}']

$config->isCached; // false

// вложенность поддерживается из коробки.
// то есть $config->myArray->subArray->string работает
```

Обрати внимание: ключ `basic_path` автоматически сопоставился со свойством `$basicPath`.

Никаких дополнительных вызовов `hydrate()`, `validate()` или ручного присваивания не требуется.

Если данные некорректны, конструктор выбросит `ValidationException`.

## 2. Принцип работы

Жизненный цикл `BasicTransfer` состоит из двух последовательных этапов.

1. **Hydration** — заполнение свойств объекта данными.
2. **Validation** — проверка заполненных свойств.

Сначала класс проходит по всем публичным свойствам наследника и пытается найти соответствующие ключи входящего массива.

После заполнения всех доступных свойств запускаются методы `validate<ИмяСвойства>()`.

Это означает, что валидация одного поля может обращаться к значениям других полей: весь объект к этому моменту уже прошёл этап маппинга.

Если при заполнении или проверке обнаружены ошибки, они собираются в общий массив.

В конце конструктор выбрасывает одно исключение со всеми найденными ошибками.

## 3. Автоматический маппинг

`BasicTransfer` сопоставляет ключи входящего массива с публичными нестатическими свойствами наследника.

Поддерживаются два варианта именования.

**CamelCase:**

```php
class ExampleTransfer extends BasicTransfer
{
    public string $basicPath;
}

new ExampleTransfer([
    'basicPath' => 'views',
]);
```

**Snake_case:**

```php
new ExampleTransfer([
    'basic_path' => 'views',
]);
```

Оба варианта заполняют одно и то же свойство.

Если в массиве присутствуют оба варианта одного ключа, приоритет имеет точное совпадение имени свойства.

### Значения по умолчанию

Свойства с установленными значениями по умолчанию не требуют обязательного присутствия во входящем массиве.

```php
class ExampleTransfer extends BasicTransfer
{
    public string $name;

    public bool $enabled = true;

    public int $timeout = 30;
}
```

Использование:

```php
$config = new ExampleTransfer([
    'name' => 'Neo',
]);
```

Результат:

```php
$config->name;    // Neo
$config->enabled; // true
$config->timeout; // 30
```

Если обязательное свойство не передано и не имеет значения по умолчанию, формируется ошибка отсутствующего поля.

### Неизвестные ключи

По умолчанию все входящие ключи должны соответствовать публичным свойствам DTO.

Например:

```php
new ExampleTransfer([
    'name' => 'Neo',
    'unknown' => 'value',
]);
```

В результате появится ошибка неизвестного ключа `unknown`.

Поведение регулируется константой `ALLOW_EXTRA`.

```php
class ExampleTransfer extends BasicTransfer
{
    protected const ALLOW_EXTRA = true;

    public string $name;
}
```

При включённой настройке дополнительные ключи игнорируются.

Значение по умолчанию:

```php
protected const ALLOW_EXTRA = false;
```

## 4. Вложенные DTO

Одна из ключевых возможностей `BasicTransfer` — автоматическое создание вложенных DTO.

Если публичное свойство типизировано классом, наследующим `BasicTransfer`, входящий массив автоматически преобразуется в экземпляр этого класса.

Например, создадим два DTO.

**CompilerTransfer.php**

```php
class CompilerTransfer extends BasicTransfer
{
    public string $basicPath;

    public array $brackets = ['{{', '}}'];

    public function validateBrackets(Rule $rule): Rule
    {
        return $rule->required()->array()->size(2);
    }
}
```

**ViewTransfer.php**

```php
class ViewTransfer extends BasicTransfer
{
    public CompilerTransfer $compiler;

    public bool $isCached = true;
}
```

Теперь передадим вложенную конфигурацию:

```php
$config = new ViewTransfer([
    'compiler' => [
        'basic_path' => 'resources/views',
        'brackets' => ['{{', '}}'],
    ],
    'is_cached' => false,
]);
```

`BasicTransfer` автоматически:

1. Обнаружит тип свойства `CompilerTransfer`.
2. Создаст экземпляр вложенного DTO.
3. Передаст ему соответствующий массив.
4. Выполнит его маппинг и валидацию.
5. Соберёт ошибки вложенного объекта в общий массив родительского DTO.

Обращение к данным:

```php
$config->compiler->basicPath;

$config->compiler->brackets;

$config->isCached;
```

Вложенные DTO могут иметь собственные вложенные DTO. Механизм работает рекурсивно.

### Пути ошибок

При вложенном маппинге сохраняется полный путь до проблемного поля.

Например:

```php
[
    'compiler' => [
        'brackets' => 'invalid',
    ],
]
```

Путь ошибки будет:

```text
compiler.brackets
```

При нескольких уровнях вложенности:

```text
view.compiler.brackets
```

Таким образом, структура ошибок повторяет структуру исходной конфигурации.

## 5. Автоматическая валидация

Для каждого свойства можно объявить собственный метод валидации.

Формат имени:

```php
validate + ИмяСвойства
```

Например:

| Свойство | Метод |
|---|---|
| `$name` | `validateName()` |
| `$basicPath` | `validateBasicPath()` |
| `$isCached` | `validateIsCached()` |
| `$dependencyInjection` | `validateDependencyInjection()` |

Методы могут быть `public` или `protected`.

Они должны быть нестатическими.

### Использование Rule

Основной способ валидации — использование `Neo\Validator\Rule`.

```php
public function validateEmail(Rule $rule): Rule
{
    return $rule
        ->required()
        ->string()
        ->email();
}
```

`Rule` уже привязан к значению соответствующего свойства и его пути.

Поэтому передавать значение вручную не требуется.

Доступны все правила, реализованные в `Neo\Validator`.

### Ручная валидация

Метод может самостоятельно проверять значение и возвращать `bool`.

```php
public function validateEnvironment(Rule $rule): bool
{
    return in_array(
        $this->environment,
        ['local', 'production', 'testing'],
        true
    );
}
```

Возвращаемые значения:

| Результат | Поведение |
|---|---|
| `Rule` | Выполняются правила объекта Rule |
| `true` | Проверка считается успешной |
| `false` | Формируется общая ошибка валидации |

Любой другой результат, включая отсутствие `return`, приводит к `LogicException`.

### Проверка взаимосвязанных свойств

Поскольку все свойства заполняются до начала валидации, можно проверять их взаимосвязи.

```php
class CacheTransfer extends BasicTransfer
{
    public bool $isCached = true;

    public ?string $cachePath = null;

    public function validateCachePath(Rule $rule): bool
    {
        if (!$this->isCached) {
            return true;
        }

        return $this->cachePath !== null;
    }
}
```

Таким образом, валидация может учитывать состояние всего DTO, а не только отдельного поля.

### Собственные ValidationException

При необходимости метод может самостоятельно выбросить `ValidationException`.

```php
public function validateName(Rule $rule): Rule
{
    if ($this->name === 'forbidden') {
        throw new ValidationException([
            'name' => ['Это имя запрещено'],
        ]);
    }

    return $rule->required()->string();
}
```

Такое исключение сразу передаётся вызывающему коду.

## 6. Обработка ошибок

Все ошибки маппинга и валидации собираются в один массив.

Исключение выбрасывается после завершения обработки полей.

Пример:

```php
try {
    $config = new ExampleTransfer([
        'name' => '',
        'timeout' => 'invalid',
        'unknown' => true,
    ]);
} catch (ValidationException $exception) {
    $errors = $exception->errors();
}
```

Структура ошибок:

```php
[
    'name' => [
        'Поле name не прошло валидацию',
    ],

    'timeout' => [
        'Поле timeout должно быть типа int, получено string',
    ],

    'unknown' => [
        'Неизвестный ключ unknown',
    ],
]
```

Конкретные сообщения зависят от правил `Neo\Validator` и реализации `ValidationException`.

### Ошибки типов

При несовпадении типа свойства и входящего значения возникает `TypeError` во время присваивания.

`BasicTransfer` перехватывает его и преобразует в обычную ошибку валидации.

Например:

```php
class ExampleTransfer extends BasicTransfer
{
    public int $timeout;
}
```

Передача:

```php
new ExampleTransfer([
    'timeout' => 'thirty',
]);
```

Приведёт к ошибке типа, а не к необработанному `TypeError`.

Важно: автоматического преобразования типов нет. Строка `'30'` не превращается автоматически в число `30`.

### Ошибки обязательных полей

Если свойство не имеет значения по умолчанию и отсутствует во входящем массиве, формируется ошибка обязательного поля.

При этом его метод валидации пропускается, поскольку значение не удалось заполнить.

## 7. Особенности свойств

`BasicTransfer` использует Reflection для определения свойств и записи значений.

### Public

Все публичные нестатические свойства наследника участвуют в маппинге.

```php
public string $name;
```

### Readonly

Readonly-свойства также могут заполняться через механизм `assign()`.

```php
public readonly string $name;
```

### Private(set)

Поддерживаются свойства с ограничением `private(set)`.

```php
public private(set) string $name;
```

Для записи используется `Closure::bind()` с областью видимости класса, в котором объявлено свойство.

Это позволяет выполнять присваивание с учётом области видимости и ограничений свойств.

### Private и Protected

Свойства `private` и `protected` не участвуют в автоматическом маппинге.

Маппинг предназначен исключительно для публичных нестатических свойств.

### Static

Статические свойства исключаются из маппинга.

## 8. Соглашения именования валидаторов

При обнаружении методов `validate...()` класс автоматически связывает их с соответствующими свойствами.

Например:

```php
public string $basicPath;

protected function validateBasicPath(Rule $rule): Rule
{
    return $rule->required()->string();
}
```

Если имя метода не соответствует существующему публичному свойству, выбрасывается `LogicException`.

Пример ошибки:

```php
public function validateBasicPaths(Rule $rule): Rule
{
    return $rule;
}
```

Если свойства `$basicPaths` нет, класс сообщит об ошибке соответствия.

Это позволяет обнаруживать опечатки в названиях валидаторов непосредственно при создании DTO.

## 9. Архитектура и внутренние методы

Внутренняя реализация `BasicTransfer` разделена на несколько специализированных методов.

| Метод | Назначение |
|---|---|
| `__construct()` | Запускает маппинг и валидацию, выбрасывает итоговое исключение |
| `hydrate()` | Выполняет маппинг и валидацию, возвращает массив ошибок |
| `mappableProperties()` | Получает публичные нестатические свойства |
| `validators()` | Находит методы `validate<Поле>()` |
| `transferClass()` | Определяет класс вложенного DTO |
| `findKey()` | Ищет входящий ключ по имени свойства |
| `snake()` | Преобразует CamelCase в snake_case |
| `mergeErrors()` | Объединяет массивы ошибок |
| `assign()` | Записывает значение в свойство с использованием Closure Binding |

### Почему hydrate() возвращает ошибки

Внутренний метод `hydrate()` не выбрасывает исключение при обнаружении обычных ошибок маппинга и валидации.

Вместо этого он возвращает массив:

```php
[
    'field' => [
        'Ошибка поля',
    ],
]
```

Это необходимо для рекурсивной обработки вложенных DTO.

Вложенный объект может вернуть свои ошибки родительскому объекту, после чего они объединяются в общий массив.

Только корневой конструктор завершает процесс выбросом `ValidationException`.

### Reflection

Для автоматизации используются следующие механизмы PHP:

- `ReflectionClass` — получение информации о классе.
- `ReflectionProperty` — анализ свойств.
- `ReflectionMethod` — обнаружение валидаторов.
- `ReflectionNamedType` — определение типа свойства.
- `Closure::bind()` — присваивание с учётом области видимости.

## 10. Настройки

На текущий момент `BasicTransfer` предоставляет одну настраиваемую константу.

| Константа | Тип | По умолчанию | Назначение |
|---|---|---|---|
| `ALLOW_EXTRA` | `bool` | `false` | Разрешает неизвестные ключи входящего массива |

Пример:

```php
class CustomTransfer extends BasicTransfer
{
    protected const ALLOW_EXTRA = true;
}
```

Константа наследуется и может переопределяться в конкретном DTO.

## 11. Ограничения и соглашения

При проектировании DTO необходимо учитывать следующие правила:

1. Маппинг выполняется только по публичным нестатическим свойствам.
2. Имена входящих ключей должны соответствовать CamelCase или snake_case.
3. Автоматическое приведение типов не выполняется.
4. Отсутствующие обязательные свойства приводят к ошибкам.
5. Неизвестные ключи запрещены по умолчанию.
6. Вложенные DTO должны наследовать `BasicTransfer`.
7. Методы `validate<Поле>()` должны быть нестатическими и возвращать `Rule` или `bool`.
8. Ошибки маппинга и валидации объединяются в одно исключение.
9. Ошибки, выброшенные непосредственно из пользовательского валидатора, передаются наружу.
10. Имена методов валидации должны точно соответствовать именам публичных свойств.

## 12. Итог

`BasicTransfer` объединяет три операции в одном базовом классе:

- **Mapping** — автоматическое сопоставление массива со свойствами объекта.
- **Hydration** — заполнение объекта, включая рекурсивное создание вложенных DTO.
- **Validation** — автоматическая проверка данных после заполнения всех свойств.

В результате наследник `BasicTransfer` становится декларативным описанием структуры данных: достаточно объявить свойства, задать значения по умолчанию и определить необходимые валидаторы.

Создание объекта автоматически выполняет весь цикл обработки.

```php
$config = new ConfigTransfer($rawConfig);
```

После успешного создания DTO гарантирует, что все обязательные поля заполнены и предусмотренные разработчиком проверки пройдены.

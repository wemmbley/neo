# Админка

Базово админка имеет `menu`, `datatable`, `pagination`, `widgets` конкретного ресурса. 
Так же админка имеет `dashboard` сущность внутрь которой входят `widgets`. 
Виджеты берутся из `.blade` файла и его личного класса-настройщика.

В дополнение ресурс может иметь кастомизированный `toolbar`, внутри которого тоже 
могут быть `widgets`, например экспорт в CSV.  

Сам ресурс - это связь к конкретной модели, и он на странице имеет 4 вида: 
`list`, `view`, `edit`, `delete`.

По умолчанию все поля фильтруются, сортируются и ищутся из коробки, но если мы 
не хотим предоставлять такой возможности, то рекомендуется для конкретного 
поля включить соответствующую опцию: `->disableFiltering()`, `->disableSorting()`
и `->disableSearching()`.

По умолчанию все удаляемые записи перемещаются через soft_delete в отдельную 
категорию в админке `Удалённые` со статусом через сколько они окончательно 
удалятся. С момента удаления одной записи проходит 7 дней и она чистится 
из таблицы автоматчиески. Либо прямо в админке еще раз выбрать и нажать 
удалить уже из этого таба. Либо в консоли `php cli admin:flush` с подтверждением 
очистки.

Базово поддерживается CSV импорт-экспорт, но на первой итерации мы под них 
делаем только заглушки и не более, реализация на будущее.

## Отображение

За отображение админки отвечают плагины Quas и Wex. Quas - отвечает за утилитарный 
подход вместо чистого CSS и являет собой прямой аналог Tailwind CSS. Wex является 
реактивной JS-библиотекой подключающеся (как и Quas) строго по CDN. В симбиозе с 
Neo они дают возможность создавать адаптивные и высоконагружные административные 
панели управления сайтом.

# Класс `Resource`

От него наследуются все ресурсы, он занимается описанием структуры ресурса. 
По умолчанию $model берётся из мени класса а затем из контейнера. Но можно 
указать явно.

```php 
class Post extends Resource
{
    public static $model = \App\Models\Post::class;
    
    public function fields(ResourceRequest $request): array
    {
        return [
            ID::make()->sortable(),
            Text::make('Title')
                ->rules(['required', 'max:255']);
        ];
    }
}
```

## Архитектура полей. 

Каждое поле обязано иметь свой .blade файл, внутрь которого передаётся переменная 
$field со всеми необходимыми свойствами, как минимум name и label на базовом 
уровне, а так же errors из сессии neo которая валидирует данные. 

## Пример виджета и его подклчюения:

```php 
class TotalUsersWidget extends Widget
{
    protected string $view = 'admin.widgets.total-users';

    public function data(): array
    {
        return [
            'total' => User::count(),
        ];
    }
}
```

Дальше HTML. Здесь помимо $widget есть доступ к переменной $admin. Она позволяет 
управлять дополнительными данными со страницы. В ней хранится общий стейт всего.

```html 
<div class="{{ $widget->class }}">
    <h3>Users</h3>
    <span>{{ $widget->total }}</span>
</div>
```

```php 
class Post extends Resource
{
    public function toolbar() 
    {
        Node::make('div', function() {
            TotalUsersWidget::make()->class('test');
        })->class('flex col-3');
    }
}
```

Теперь в тулбаре на `list` странице будет находится новый виджет. 
Универсальный элемент `Node` позволяет создать любой вложенности 
контейнера для обёртки в нужные классы, айдишники и с любыми атрибутами: 
`->class()`, `->id()`, `attribute()`. Пример: `attribute('data-hex="123"')`
